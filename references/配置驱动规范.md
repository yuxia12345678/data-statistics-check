# 配置驱动规范（换行业 / 加表 / 改字段，源码零改动）

> **本文件是「配置驱动能力」的唯一定义处**：哪些改动只需改 JSON、配置键的确切语义与边界。
> 口径与公式模板见《口径与公式规范.md》，样式取值见《样式规范.md》。

## 总原则

- **唯一事实源 = 一份业务 JSON**。生成侧（`stat_engine.py`）与自检侧（`verify.py`）
  读写同一份配置，且**共用同一个表头类型解析器**（`config_validator.kind_of_name`），
  避免两侧对同一格给出不同期望。
- 代码中**不出现任何业务字段名 / 表名**；表名与表数取自配置 `sheet_order`。
- 判定「能否只改配置」的口径：**生成结果 + 46 项自检同步生效**，不需要动 `.py` 文件。

## §1 输入结构（换行业数据的入口）

| 配置键 | 含义 | 说明 |
|---|---|---|
| `input.sheet_name` | 源工作表名 | 单工作表输入 |
| `input.header_row` | 表头所在行号 | **产物数据行固定从第 3 行开始**，与源表表头行位置解耦 |
| `input.data_end.last_row` | 数据末行（写死） | 优先级最高，最直接 |
| `input.data_end.stop_keywords` | 停止词，如 `["合计","总计","小计"]` | 首列（去空格后）以这些词开头即停止 |
| `input.data_end.stop_on_blank_first_col` | 首列为空即停止 | 用于排除表尾页脚行 |

三者可组合；都不配 → 原口径「最后一个非空行」。

> **为什么需要 `data_end`**：其他行业报表常在表尾带「合计」行与页脚行
> （如「内容由 AI 生成」）。若不声明停止条件，这些行会被当成明细参与统计
> （结果直接算错），数值列还会因混入 `=SUM(...)` 文本变成 object 类型而报错。

## §2 新增工作表：`extra_sheets`

顶层可选数组，**每项 = 一张新工作表**，表名/列/口径/排序/合计行全部声明式。
自检侧同步新增 `R5x`（行数）、`R6x-<表名>`（逐格数值）、`R7x`（排序）三组通用断言。

### 2.1 `type = "group"`（逐分组一行）

```json
{
  "type": "group",
  "sheet_name": "分组统计",
  "sheet_title": "分组统计",
  "group_field": "分组字段",          // null = 全表汇总一行
  "serial": "序号",                    // 不要序号列则省略
  "total_row": true,
  "total_label": "合计",
  "sort_by": "金额(元)",              // 必须是 columns 里的输出列名；省略 = 按首次出现顺序
  "sort_desc": true,
  "columns": [
    {"name": "分组字段", "kind": "cat",   "agg": "group"},
    {"name": "金额(元)",  "kind": "money", "agg": "sum", "field": "金额(元)"},
    {"name": "利润率",   "kind": "pct",   "agg": "ratio",
     "numerator": "利润(元)", "denominator": "金额(元)"}
  ]
}
```

### 2.2 `type = "pivot"`（行列交叉表）

```json
{
  "type": "pivot",
  "sheet_name": "行列交叉表",
  "sheet_title": "行标签 × 列标签 金额交叉表（元）",
  "row_field": "行标签", "col_field": "列标签", "value_field": "金额(元)",
  "agg": "sum",                        // sum | count
  "col_sort": "desc",                  // desc = 按列合计降序；省略 = 首次出现顺序
  "total_row": true, "total_col": true, "total_label": "合计"
}
```

交叉表的列由**数据动态展开**（`col_field` 的取值 → 列头），因此**不要**把列头名写进 `field_kind`：
其格式与对齐按该表 `value_field` 的类型反查（生成侧与自检侧同规则）。

### 2.3 列聚合 `agg` 一览

| `agg` | 需要字段 | 单元格公式（全部动态引用「原始数据」） |
|---|---|---|
| `group` | — | 分组值本身（字面量） |
| `seq` | — | `=ROW()-2` |
| `const` | — | 固定文本（`literal`） |
| `sum` | `field` | `SUMIFS(原始数据!$<列>…, 原始数据!$<分组列>…, $B3)` |
| `count` | — | `COUNTIFS(原始数据!$<分组列>…, $B3)` = 组内明细行数 |
| `nunique` | `field` | `SUMPRODUCT((分组列=$B3)/COUNTIFS(域,域&"",分组列,分组列&""))` |
| `first_non_null` | `field` | `INDEX+MATCH` 取组内第一条非空 |
| `last_non_null` | `field` | 同上（区间语义） |
| `distinct_join` | `field` | 组内非空去重拼接（**公式化例外**，写文本；`join_separator` 可配） |
| `ratio` | `numerator` / `denominator` | 见下 |

`ratio` 的分子 / 分母写法：

- `"金额(元)"` —— 引用**本表**同名输出列（列序不受限，内部两遍求值）
- `"global:金额(元)"` —— 引用该源字段的**全表合计** `SUM(原始数据!…)`
- `"literal:0.5"` —— 字面常量
- `{"minuend_field": "金额(元)", "subtrahend_field": "成本(元)"}` —— **两列合计之差**

### 2.4 合计行语义（`total_row=true`）

| 列 `agg` | 合计行 |
|---|---|
| `group` | 写 `total_label`（默认「合计」） |
| `sum` / `count` / `nunique` | 全表聚合公式（`SUM` / `COUNTA` / 非空去重计数），仍引用「原始数据」 |
| `ratio` | 用**合计行自身**的单元格做除法 |
| `seq` / `const` / 文本类 | 留空（文本没有「全表合计」的语义） |

合计行整行加粗，便于识别。

## §3 既有工作表「加 / 删 / 改字段」

既有 8 张表（数量与表名由 `sheet_order` 声明）的字段集**本来就是明文清单**，改字段 =
改 JSON 里对应的清单 + 同步登记类型。**代码零改动。**

| 工作表 | 字段清单键 | 支持的聚合 / 口径键 |
|---|---|---|
| 同X合并汇总 | `task1_group_merge.agg_strategy_list` | `value` / `first_non_null` / `distinct_join`(+`join_separator`) / `sum` |
| 分类汇总 | `task2_special_agg.metrics` | `sum` / `nunique` / `count`；`ratio_field_name` 改列名、`ratio_denominator` 改分母 |
| 各维度表 | `task3_multi_dim.dim_metrics` + `derived_ratio_list` | `sum` / `nunique`；派比分母支持同表指标名或 `全局<指标名>` |
| 统计总览 | `task3_multi_dim.overview_metrics` | `sum` / `ratio` / `nunique` / `count_rows`，`divide` 可缩放 |

要点：

- **加字段** = 在清单里加一项；**删字段** = 删掉那一项；**改字段** = 改 `field_name` /
  输出名 / `source_field`。三者在配置里同级。
- 每张表还要把新列头登记进对应的 `*_fields`
  （`num_fields` / `int_fields` / `pct_fields` / `date_fields` / `cat_fields` / `text_fields`）——
  它们驱动**数字格式与对齐**，登记漏了 `apply_sheet_format` 会**直接报错**（不会静默放过）。
- 维度表数量、表名、顺序同样只改 `dim_list` 与 `sheet_order`。
- 分类汇总的「占比」分子列 = `metrics` 中「来源字段 == `amount_field`」的那一列
  （配置反查，不写死列号），因此增删或重排 `metrics` 后分子列自动跟随。

## §4 数字格式与对齐的唯一判据：`field_kind`

`field_kind` 把**表头名 → 类型**（`money` / `num` / `int` / `pct` / `date` / `cat` / `text`），
生成侧与自检侧都据它设格式、判对齐（自检 R8 / R9）。

解析顺序（`kind_of_name`，两侧共用）：

1. 表头原名，如 `总合同金额`
2. 去掉末尾括号说明，如 `总合同金额（万元）` → `总合同金额`
3. 再去掉「总」前缀，如 `总合同数` → `合同数`

> 声明式列（`extra_sheets.columns`）的 `kind` 必须与 `field_kind` 登记**一致**
> （`money` 与 `num` 视为等价：`field_kind` 用 `money`，样式清单用 `num`）。
> 不一致时 `config_validator` 直接报错，避免生成侧与自检侧各说各话。

## §5 边界与已知例外

- 输入为**单个工作表**；表**数量**由 `profiles.<profile>.sheet_order` 声明，`extra_sheets`
  可插入任意位置（剔除它们后，其余表的相对顺序必须与构建顺序一致）。
- 文本类聚合（`distinct_join`）在 Excel 中**没有非数组的稳定写法**
  （`TEXTJOIN`/`UNIQUE`/`FILTER` 需 Excel 365），故该列写文本字面量——这是唯一的公式化例外；
  自检 R3a 只断言**数值格**必须是公式。
- 统计值一律引用「原始数据」区间；不支持需要 `Ctrl+Shift+Enter` 的数组公式。
- 「原始数据」零美化（`style_setting.raw_beautify=false`）时，其冻结窗格/列宽属源文件状态，
  由 R2d 与源表逐项比对，R13 不对它断言。
- 源表自带的公式（如报表尾部的「合计」行）会被原样保留，并在保存后**写回缓存值**，
  保证程序化读取与源表一致（R2a）。
