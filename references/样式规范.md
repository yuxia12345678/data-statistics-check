# 统一可视化美化规范（可执行参数）

产物侧的样式参数集中在 `config/contract_repayment.json`，由 `scripts/excel_styler.py` 落地；
`scripts/verify.py` 的 R8–R16 逐格核验，其期望值**同样从这份 JSON 读取**（同一事实源）。
改样式时只改 `config/contract_repayment.json`，生成与校验同步生效。

## 1. 布局：每张表都是"标题行 + 表头行 + 数据区"

| 行 | 内容 | 说明 |
|---|---|---|
| 第 1 行 | 跨全部列合并的大标题 | 例外见下方「原始数据」 |
| 第 2 行 | 表头（字段名） | 与源文件表头行位置一致，便于公式区间对齐 |
| 第 3 行起 | 数据 | 冻结窗格 `A3`，前两行始终可见 |

标题文字（取自《附件2-示例》）：

| 工作表 | 第 1 行标题 |
|---|---|
| 原始数据 | 原始数据明细（`spec` profile 下不覆盖源第 1 行，见 §6） |
| 同合同号合并汇总 | 同一合同号数据合并汇总 |
| 未回款原因分类汇总 | 未回款原因分类汇总 |
| 统计总览 | 数据统计总览 |
| 区域统计 | 区域维度统计分析 |
| 部门统计 | 部门维度统计分析 |
| 账龄统计 | 账龄维度统计分析 |
| 客户分类统计 | 客户分类维度统计分析 |

## 2. 颜色与字体

| 元素 | 参数 |
|---|---|
| 标题行 | 底色 `FF1F4E78`（深蓝、低饱和度）；字体 微软雅黑 14 加粗；字色 `FFFFFFFF`；水平+垂直居中；自动换行；行高 37.35 |
| 表头行 | 底色 `FF0070C0`（低饱和度蓝）；字体 微软雅黑 11 加粗；字色 `FFFFFFFF`；水平+垂直居中；自动换行；行高 32.45 |
| 数据区 | 字体 微软雅黑 11；字色 `FF000000`；垂直居中 |
| 斑马纹 | 奇数数据行（第 3、5、7…行）底色 `FFEBF1F8`，偶数行无底色 |
| 边框 | 浅灰 `FFBFBFBF`，`thin` |

## 3. 边框：只保留水平线

题目要求"仅保留浅灰色水平边框，无多余边框线条"，因此 `spec` profile 下：

- 数据区每个单元格：只有 `bottom = thin FFBFBFBF`，无左右边框、无上边框
- 表头行：`top + bottom = thin FFBFBFBF`，形成表头分隔线
- 标题行：无边框

《附件2-示例》实际是四边 `thin` 全边框，与题目正文冲突。切换到示例形态：
把 `config/contract_repayment.json` 里 `profiles.example.border_mode` 改为 `all`（或直接 `--profile example`）。

## 4. 对齐

| 字段类型 | 对齐 | 字段 |
|---|---|---|
| 数值（金额、比率、计数、序号） | 右对齐 | 合同金额、未开票金额、开票金额、回款合计、开票未回款、合同数、涉及合同数、涉及笔数、回款率、未回款占比、占比、序号 |
| 文本 | 左对齐 | 合同号、责任人、指标 |
| 日期 | 居中 | 开票日期 |
| 分类 | 居中 | 区域、客户分类、部门、账龄、未回款原因分类 |

依据题目正文"文本字段左对齐；数值字段右对齐；日期、分类字段居中对齐"。
字段 → 类型的映射表是 `config.FIELD_KIND`，新增字段时在该表登记即可。

《附件2-示例》把开票日期设为右对齐、把区域/部门/账龄/客户分类设为左对齐，与题目正文冲突；
`--profile example` 可切换。

`区域`、`部门` 归入"分类"是因为它们是任务3 的统计维度（分类字段）；
`合同号`、`责任人` 归入"文本"是因为它们是标识与人名。该判定已写入 `config.FIELD_KIND`。

## 5. 数字格式与列宽

| 类型 | 格式串 | 示例显示 |
|---|---|---|
| 金额 | `#,##0.000` | `911,876.017` |
| 比率 | `0.00%` | `25.43%` |
| 计数 | `0` | `463` |
| 开票日期 | `@`（文本，维持源文件原始录入格式） | `20250801` |

金额小数位以题目正文为准（千分位 + 3 位小数）；《附件2-示例》用的是 2 位小数。
切到示例口径只需把配置的 `amount_number_format` 改成 `#,##0.00`，无需改代码。

**列宽自动适配（中文按全角字符标准）**：

```
显示宽度 = Σ(全角字符计 2，半角字符计 1)      # unicodedata.east_asian_width in ('W','F')
列宽     = clamp(max(表头宽度, 各数据行显示宽度) + padding, min, max)
```

- 上下限与内边距由 `config/contract_repayment.json` 的 `col_width_min` / `col_width_max` /
  `col_width_padding` 控制（当前 `8` / `40` / `3`）
- 实现：`scripts/excel_styler.py` 的 `display_width()`（全角判定）+
  `format_display()`（按数字格式渲染显示文本）+ `auto_fit_column_width()`

> ⚠️ 全角判定必须用 `unicodedata.east_asian_width ∈ ('W','F')`，**不要**用
> `'\u4e00' <= ch <= '\u9fff'`：后者既漏掉全角标点（，。（）「」）、全角字母数字、
> 假名、谚文，也容易因源码里被写成 `'\\u4e00'`（双反斜杠）而**恒为 False**，
> 导致中文实际按 1 个宽度计算。该 bug 曾真实存在于 `excel_styler.py` 中。

关键实现细节：参与列宽计算的必须是**单元格最终显示出来的样子**
（金额按 `#,##0.000` 格式化后的字符串、比率按 `0.00%` 格式化后的字符串），
**不能是公式文本**。因此引擎会把注入的公式**缓存值**（`display_values`，{坐标: 值}）
交给列宽估算：公式格按其真实显示数值计宽，取不到缓存值时该格跳过、绝不拿公式串量宽。
《附件2-示例》的列宽明显失真（例如「回款率」列宽 28.29、「未回款占比」列宽 30.86，
而实际显示内容只有 6–7 个字符），推断是其生成流程按公式字符串长度算了列宽；
本实现按显示值计算，避免同一问题。

「原始数据」表的列宽同样按此规则重算（列宽属于工作表级属性，不改变单元格值与数字格式）；
其数字格式由引擎以 `set_number_format=False` 逐格保留源样。

## 6. 「原始数据」表的特殊处理

题目存在两条互相冲突的硬性要求：

- 硬性规则(2) / 注意事项(1)：完整保留原始数据，**不得修改内容、行列顺序、单元格格式**，任何改动均视为违规扣分
- 统一美化规范：**所有输出工作表**必须统一格式标准，全程合规无遗漏

`spec` profile 的折中方案（也是默认行为）：

| 项 | 处理 |
|---|---|
| 单元格值 | 一律不动（含 1000 行明细、含空值、含 E 列文本日期） |
| 行列顺序 | 一律不动（不做任何排序、不删空列、不增行） |
| 数字格式 | 一律不动（金额保持源文件 `#,##0.000`，日期保持 `@`） |
| 第 1 行 | 保留源文件原样（`B1 = 单位：万元`），**不**覆盖为合并大标题 |
| 表头行样式 | 叠加蓝底白字加粗居中 |
| 数据区样式 | 叠加斑马纹、浅灰水平边框、按类型对齐 |
| 列宽 / 冻结 | 叠加自动列宽、冻结 `A3` |

理由：值、行列顺序、数字格式是"数据"本体，一律零改动；
填充色、字体、边框、对齐、列宽属于"统一可视化美化"，题目要求全表生效。
保留 `B1 = 单位：万元` 是因为它是源数据的一部分，且金额单位对报表解读至关重要
（统计总览的指标标签也据此写作「总合同金额（万元）」）。

三档可选：

| 参数 | 行为 |
|---|---|
| 默认（`spec`） | 上表方案：数据零改动 + 叠加美化 |
| `--raw-strict` | 「原始数据」完全不加任何美化，最严格的原样复制 |
| `--profile example` | 按示例形态：覆盖第 1 行为大标题、金额 2 位小数、日期右对齐、四边框 |

## 7. 条件格式（任务2 专项）

题目要求"为不同未回款分类单元格设置差异化柔和背景条件格式"。
实现用 `openpyxl.formatting.rule.FormulaRule`，作用域为分类列的数据区，
每个分类一条规则、一种柔和底色，命中判定用 `EXACT($B3,"分类名")`（区分大小写与空格）：

```
柔和底色调色板（循环使用）：
FFFDE9D9  FFDCE6F1  FFEBF1DE  FFE4DFEC
FFF2DCDB  FFDAEEF3  FFFFF2CC  FFEAF1DD
```

用真条件格式而不是静态填充的原因：数据行增删后规则依然生效，符合"动态"要求；
静态填充一旦行数变化就会出现底色与分类错位。

本数据集「未回款原因分类」全为空 → 分类数 0 → 规则数 0，属预期结果（无数据行可上色）。
《附件2-示例》全文件没有任何条件格式规则，这一点未跟随示例，以题目正文为准。
