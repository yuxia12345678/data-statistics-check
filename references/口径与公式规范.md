## 1. 任务1：同一合同号多行合并为一行

分组主键 = 合同号（源数据 1000 行 → 463 个不同合同号，284 个合同号有多行，最多 10 行）。

| 字段 | 规则 | 公式 |
|---|---|---|
| 序号 | 全新连续序号 1..463 | `=ROW()-2` |
| 合同金额、未开票金额、开票金额、回款合计、开票未回款 | 按合同号求和 | `=SUMIF('原始数据'!$D$3:$D$1002,$D3,'原始数据'!$F$3:$F$1002)` |
| 区域、客户分类、开票日期、部门、责任人、账龄 | 组内第一条**非空**有效值 | `=IFERROR(INDEX('原始数据'!B$3:B$1002,MATCH(1,INDEX(('原始数据'!$D$3:$D$1002=$D3)*('原始数据'!B$3:B$1002<>""),0),0)),"")` |
| 未回款原因分类 | 组内非空内容去重后按「；」拼接（分隔符 = 配置 `join_separator`；题目只要求“统一”，选分号以便与内容里可能出现的顿号区分） | 计算结果文本（见下方"公式化例外"） |

**行序**：按合同号升序（从小到大）。

> 变更记录：初版沿用《附件2-示例》的「按合同金额降序」（463 行合同号 + 合同金额逐行比对，
> 匹配 463/463）。2026-10-03 按需求改为**按合同号升序**，**与示例不同**；
> 该差异已登记在 `与示例文件的差异.md`。实现见 `stat_engine.get_contract_list()`，
> 自检见 `verify.py` 的 R7-合并。

**"第一条非空值"公式说明**：内层 `INDEX(数组,0)` 让数组在 Excel 中无需 Ctrl+Shift+Enter
即可求值，LibreOffice 同样支持。已用"剥离全部缓存值 → LibreOffice 从零实算 → 与 Python
独立计算逐格比对"的方式验证：19611 个单元格 0 处不一致。
本数据集这 6 个字段无任何空值，因此该公式与简化版 `INDEX+MATCH(合同号)` 结果等价；
保留健壮写法是为了字段出现空值时仍然正确。

### 公式化例外（共两类，均已登记）

题目硬性规则(1) 要求"所有数据计算禁止硬编码数值，必须全部使用动态公式"。本 Skill 的
**统计数值单元格 100% 为动态公式**；唯一写入"文本字面量"的是下面两类**非数值**单元格，
特此登记，以便评审对照时判定为"合规例外"而非"硬编码"。

**例外 A —— 分组键列的键取值文本（合并表 / 四维度表 / 原因表）。**
合并表「合同号」列、四维度表的「<维度>」列、原因表的「未回款原因分类」列，写入的是该分组的
**键取值文本**（如 `HT2025…`、`华南-海南`）。它们不是"统计结果"，而是
`SUMIF` / `SUMIFS` / `COUNTIF` / `COUNTIFS` / `SUMPRODUCT` 的**条件值**——没有条件值就写不出
动态公式，故必须以文本形式落到单元格。要点：

- 键**取值由源数据动态得出**（`stat_engine` 按配置的 `group_keys` / `dimensions` / `category_field`
  对源表去重并排序后落值），不是人工写死的常量；源表增删分组值，重跑即自动增减对应行。
- 由这些键派生的**全部数值**（金额、计数、比率）仍是引用 `'原始数据'!$X$3:$X$1002` 的动态公式。
- 自检 R5a / R5a-维度 / R6a 断言"行数 = 源表对应唯一值个数""行序 = 按开票未回款降序"，
  键集合与顺序均被独立核验，不存在写死空间。
- **边界**：源表新增一个此前不存在的分组值时，须**重跑 `run_skill.py`** 才会出现该分组的新行
  （行集合在生成时确定）。属结构性约束，并见 §6「已知边界与可配置路径」。

**例外 B —— 备注字段的拼接结果文本。** `未回款原因分类` 的"去重后拼接"是文本聚合，
Excel 没有稳定的非动态数组写法（`TEXTJOIN+UNIQUE+FILTER` 依赖 Excel 365 动态数组，
LibreOffice 与旧版 Excel 不兼容，评审环境不可控）。因此该列写入计算结果文本。
说明三点：① 它是文本而非数值，题目的"禁止硬编码"针对的是数据计算；
② 该字段为空时拼接结果为空文本——**不得写入 `nan`**：源表空单元格经 pandas 读入为
`NaN`，判空必须同时识别 `None` / `NaN` / 空白串（2026-10-03 修复，此前会被拼成字面量 "nan"）；
③ 该例外已在 `构建过程文档.md` 与 `SKILL.md` 中登记。

## 2. 任务2：未回款原因分类汇总

工作表列结构：`序号 | 未回款原因分类 | 开票未回款 | 涉及合同数 | 涉及笔数 | 占比`

| 指标 | 公式 |
|---|---|
| 开票未回款 | `=SUMIF('原始数据'!$O$3:$O$1002,$B3,'原始数据'!$K$3:$K$1002)` |
| 涉及合同数 | `=SUMPRODUCT(('原始数据'!$O$3:$O$1002=$B3)/COUNTIFS('原始数据'!$D$3:$D$1002,'原始数据'!$D$3:$D$1002&"",'原始数据'!$O$3:$O$1002,'原始数据'!$O$3:$O$1002&""))` |
| 涉及笔数 | `=COUNTIF('原始数据'!$O$3:$O$1002,$B3)` |
| 占比 | `=IF((SUM('原始数据'!$F$3:$F$1002)-SUM('原始数据'!$J$3:$J$1002))=0,"",C3/(SUM('原始数据'!$F$3:$F$1002)-SUM('原始数据'!$J$3:$J$1002)))`，百分比格式保留 2 位小数 |

- **占比分母 = 「原始数据」合同金额合计 − 回款合计合计**
  （= 统计总览的「总合同金额」−「总回款合计」，当前数据 = 911876.017 − 231845.383 = 680030.634）。
  **两列合计直接由「原始数据」求和，不引用统计总览**；字段由配置
  `task2_special_agg.ratio_denominator`（`minuend_field` / `subtrahend_field`）驱动。
  注意与任务3 的"未回款占比"分母（全局总合同金额）不同，见下节。
- **口径对照（脚注）**：题目正文称"占全部总未回款金额的比例"。若将"全部总未回款金额"理解为
  「开票未回款合计」（当前数据 = 210976.108），则占比分母应取该值；本 Skill 默认口径
  「合同金额合计 − 回款合计合计」（680030.634）是从官方示例文件反推、并在区域/账龄/客户分类
  三处独立验算吻合到小数点后 16 位的口径。两种理解仅为分母定义差异，改配置
  `task2_special_agg.ratio_denominator` 的 `minuend_field` / `subtrahend_field` 即可一键切换，
  无需改代码。
- 排序：按开票未回款降序（题目正文明确）。
- 空值处理：`未回款原因分类` 为空的行**不构成一个分类**，分类数一律由数据动态决定：
  该字段全空 → 分类数 0 → 本表只有标题行与表头行；有非空分类 → 每个分类一行。
  > 🔁 2026-10-04 复核：**当前交付数据集该列 1000 行全为空**，分类数 0，本表只有标题行与表头行。
- ⚠️ **去重计数的条件侧必须带 `&""`**（见下表「涉及合同数」）：`COUNTIFS` 的条件若是**裸单元格
  引用且为空**，Excel 会按 `0` 处理（而非空白），分母遂为 0 → `0/0` → **`#DIV/0!`**。
  本表分组的来源列（未回款原因分类）恰好大量为空，是最容易踩中该坑的一张表；
  同理适用于任务3 四维度表的「合同数」。`verify.py` R18 对所有 `COUNTIF(S)` 的条件参数直接断言。
- 分类列底色：按题目正文任务2(4) 启用**差异化柔和背景条件格式**（`style_setting.reason_soft_cf = true`，
  每类一色，命中判定 `EXACT($B3,"分类名")`；调色板见 `样式规范.md` §7）。
  两个坑已登记：① 颜色须 8 位 ARGB；② 公式须**锚定区间首行**，写成分类自己那一行则除首行外全部不命中。

## 3. 任务3：四维度统计分析

四个固定维度：区域（34 个取值）、部门（10 个）、账龄（3 个）、客户分类（8 个）。
每个维度一张独立工作表，列结构统一为 9 列：

`序号 | <维度> | 总合同金额 | 总开票金额 | 总回款合计 | 总开票未回款 | 合同数 | 整体回款率 | 未回款占比`

| 指标 | 公式（以区域为例，`$B3` 为本行维度值） |
|---|---|
| 总合同金额 | `=SUMIF('原始数据'!$B$3:$B$1002,$B3,'原始数据'!$F$3:$F$1002)` |
| 总开票金额 | 同上，值区间换 `$I$`（开票金额） |
| 总回款合计 | 同上，值区间换 `$J$`（回款合计） |
| 总开票未回款 | 同上，值区间换 `$K$`（开票未回款） |
| 合同数 | `=SUMPRODUCT(('原始数据'!$B$3:$B$1002=$B3)/COUNTIFS('原始数据'!$D$3:$D$1002,'原始数据'!$D$3:$D$1002&"",'原始数据'!$B$3:$B$1002,'原始数据'!$B$3:$B$1002&""))` |
| 整体回款率 | `=IF(C3=0,"",E3/C3)` |
| 未回款占比 | `=IF(SUM('原始数据'!$F$3:$F$1002)=0,"",F3/SUM('原始数据'!$F$3:$F$1002))` |

排序：按开票未回款降序（题目正文明确）。同值时按维度值字典序稳定排序，保证可复现。

### 关键口径与验证证据

**合同数 = 组内不同合同号的个数**，不是明细行数，也不是合并表中该维度值的行数。
验证（《附件2-示例》值 vs 源数据三种候选口径）：

| 分组 | 示例值 | 明细行数 | 组内不同合同号 | 合并表行数 |
|---|---|---|---|---|
| 区域·华南-海南 | 29 | 29 | **29** ✓ | 14 |
| 部门·三部 | 95 | 104 | **95** ✓ | 42 |
| 账龄·1-2年 | 246 | 322 | **246** ✓ | 146 |
| 客户分类·事业单位 | 120 | 131 | **120** ✓ | 65 |

四维度全部 55 个分组、495 个单元格与示例逐格比对，0 处不一致。
注：各维度分组的合同数之和会大于 463，因为同一合同号的不同明细行可以落在不同维度取值上，
这是口径本身决定的，不是重复计算错误。

**未回款占比的分母是"全局总合同金额"（911876.017），不是本组开票金额，也不是全局开票金额。**
验证：区域·华南-海南 `11774.220 / 911876.017 = 0.01291208429709145`，与示例值完全一致；
账龄·1-2年 `78928.404 / 911876.017 = 0.08655606960655485`，同样完全一致。

**整体回款率 = 组内回款合计 ÷ 组内合同金额。**
验证：区域·华南-海南 `5325.631 / 23982.43 = 0.2220638609181805`，与示例一致。

## 5. 禁止硬编码的实现方式

题目要求"所有数据计算禁止硬编码数值，必须全部使用动态公式"，同时评审很可能用程序
（`openpyxl data_only=True` / pandas）读取结果文件核对数值。这两个要求存在技术冲突：
openpyxl 写公式时不产生缓存值，程序读取会得到 `None`。

解决方案（`scripts/cached_values.py`）：

1. `stat_engine.py` 写入**真实公式**，同时用独立的 Python 计算路径（pandas）算出每个公式格的期望值；
2. 保存后直接改写 OOXML，为每个含 `<f>` 的单元格补上 `<v>` 缓存值；
3. 设置 `calcPr/@fullCalcOnLoad="1"`，Excel/WPS 打开时整簿重算。

结果：文件同时具备"动态公式"和"可程序化读取的数值"，且不依赖 LibreOffice 等外部中间件
（题目明确不提供额外环境资源）。当前数据集共产出 **6004 个公式单元格**，
6004 个缓存值全部注入，公式错误 0 处。

**验证方式（关键）**：把全部缓存值剥离（该轮为题目原版数据集，6004 个），交给 LibreOffice 从零实算，
再与 Python 独立计算结果逐格比对 —— 19611 个单元格，0 处不一致，0 处空值。
这证明公式本身正确，而不是缓存值自证。
> ⚠️ **该验证的边界**：那一轮数据集「未回款原因分类」全空（任务2 无数据行），
> 四维度的取值也都不含空白，因此**没有覆盖“分组列存在空白单元格”**的情形；
> 分组去重计数在那里会因条件为空白而除零——这正是下文 `&""` 说明和 `verify.py` R18 要堵的漏洞。
（注意：若不剥离缓存值，LibreOffice 的 `--convert-to` 默认不重算，会原样搬运输入的缓存值，
这种"验证"是无效的。本 Skill 的开发过程中专门用"故意写错一个缓存值"的反向测试确认了这一点。）

## 6. 已知边界与可配置路径（换表数 / 换维度 / 换平台）

本 Skill 的适配面是**"同结构明细表 → 多工作表统计报表"**这一族，边界与对应的配置路径如下，
均为"改配置即可"，不需要改代码：

| 边界点 | 现状 | 可配置路径（`config/contract_repayment.json`） | 是否需改代码 |
|---|---|---|---|
| 输入结构 | 单工作表（默认 `Sheet1`）、表头固定在第 2 行、14 字段 | `input.sheet_name` / `input.header_row`（表头行）、`field_kind`（字段类型表）、`task1_group_merge.primary_key`（业务主键）、`task2_special_agg.group_field`（分类字段）、`task3_multi_dim.dim_list[].dimension_field`（维度字段） | 否 |
| **源表表头不在第 2 行**（其他行业报表） | 支持 | `input.header_row` 声明真实表头行；产物数据行恒为第 3 行，与源表行号解耦 | 否 |
| **表尾带「合计」行 / 页脚行** | 支持 | `input.data_end`：`last_row` 或 `stop_keywords`（如 `["合计","总计","小计"]`）+ `stop_on_blank_first_col`；不声明则会被当成明细算错 | 否 |
| 输出表数量 | 默认 8 张（题目规定），**数量不写死** | `profiles.<profile>.sheet_order`（表名与顺序）、`output_sheet_names` / `sheet_titles` | 否 |
| **新增工作表** | 支持任意多张 | 顶层 `extra_sheets`：`type=group`（逐分组一行，可编号/合计行/排序）或 `type=pivot`（行列交叉表）；表名一并加进 `sheet_order` | 否 |
| 维度个数 | 默认 4 个（区域/部门/账龄/客户分类） | `task3_multi_dim.dim_list`（增删维度即增删对应统计表） | 否 |
| 指标项 | 每维度 7 项（题目规定） | `task3_multi_dim.dim_metrics`（字段→聚合方式）+ `task3_multi_dim.derived_ratio_list`（派生比率，如回款率 / 占比） | 否 |
| **既有表加 / 删 / 改字段** | 支持 | 合并表 `agg_strategy_list`；分类汇总 `metrics`（+ `ratio_field_name` / `ratio_denominator`）；维度表 `dim_metrics` / `derived_ratio_list`；总览 `overview_metrics`；并同步登记 `*_fields` 与 `field_kind` | 否 |
| 分组键集合 | 生成时按源数据确定 | 源表新增分组值后**重跑 `run_skill.py`** 即自动出现新行（见 §1 例外 A 边界） | 否 |
| 平台 / Python 版本 | 随包 wheel 为 Windows + CPython 3.11（与评测环境一致） | 换平台或版本时按 `vendor/README.md` 重新拉取对应 wheel，替代随包 wheel 即可 | 否 |

> 说明：表数 / 维度数被 `config_validator.py` 按配置断言，是为了保证"配置写了什么、产物就是什么"；
> 要改成别的表数或维度数，改的是 `profiles.*.sheet_order` 与 `task3_multi_dim.dim_list`，
