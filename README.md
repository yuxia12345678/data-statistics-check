# 合同数据统计核对 Skill

> 企业合同开票与回款明细自动化统计工具
> Python `3.11`｜依赖 `openpyxl` + `pandas` + `numpy`｜支持离线安装（`vendor/`）
>
> **本文件是面向人的项目说明，不是执行依据。** 口径、命令与交付校验一律以 `SKILL.md` 为准。

## 一、功能

一个输入 Excel → 一个输出 Excel（8 张工作表）。完成同一合同号多行合并、未回款原因分类汇总、
区域/部门/账龄/客户分类四维度统计分析；全部统计单元格为 Excel 原生动态公式，
原始明细零篡改，全工作表统一美化。

## 二、应用场景

1. **合同回款对账统计（本项目主要场景）**：合同多行合并、未回款原因分类统计，
   按区域 / 部门 / 账龄 / 客户分类做多维度回款分析。
2. **同类明细行合并汇总**：同一业务主键多条流水合并为单条——数值求和、文本取首条非空、
   备注去重拼接（订单流水、报销记录等）。
3. **分类专项统计**：按某分类字段统计金额、条数、占比。
4. **多维度透视统计**：同一套明细按多个维度分别出表，公式联动刷新。

> ✅ 前提：输入为结构化 Excel 明细表；输出需 Excel 原生公式；要求原始数据完整保留。
> ❌ 不适用：非结构化 PDF / 图片识别；需要复杂自定义业务逻辑的场景。

## 三·补、可配置性（换业务不改代码）

Skill 不与合同案例强绑定：字段名、聚合口径、分组维度、排序字段、输出表名与顺序、
样式与数字格式**全部写在业务 JSON 里**，主程序代码中不写死任何业务字段名与表名
（表名校验的期望值也取自配置 `profiles.<profile>.sheet_order`）。

**交付自检同样配置驱动**：`verify.py` 的 46 条断言中凡涉及业务字段的部分
（业务主键、分类字段、金额字段、指标字段、排序字段、总览指标口径）一律从配置反查，
代码里不出现任何业务字面量。因此**同一份 `verify.py` 可直接核验第二套业务案例**。

`示例/案例B-订单流水统计/` 是本项的第二套实测案例：换成
「订单号 / 订单金额 / 发货金额 / 已结算金额 / 未结算金额 / 库龄 / 渠道分类」后，
**同一条命令、同一份代码**照常产出 8 张新命名的工作表，公式仍然全部动态引用「原始数据」，
且 **46 项交付断言同样全部通过**。两套案例的差异对照与运行命令见 `示例/README.md`。

## 四、安装

**通常不用装。** `run_skill.py` / `verify.py` 启动时会**自动做依赖自检**：
齐全就跳过安装直接跑；缺失就用工程内 `vendor/` **离线补齐**（失败再退联网），补齐后继续执行。

需要显式安装时：

**联网环境：**

```bash
pip install -r requirements.txt
```

**离线环境（无外网）：** 需先把 `vendor/` 放齐（含全部依赖 wheel，Windows / CPython 3.11），全程不联网：

```bash
./install_offline.sh          # bash / Git Bash
install_offline.bat           # Windows
# 等价于：
python -m pip install --no-index --find-links vendor -r vendor/requirements.lock.txt
```

详见 `vendor/README.md`（含锁定版本清单与其它平台重新拉取方法；该目录按需放入，非常驻）。

**只检测、不安装**（用于环境巡检）：

```bash
python scripts/deps_check.py --list     # 打印依赖清单与当前状态
python scripts/deps_check.py --check    # rc=1 表示有缺失
python scripts/deps_check.py --offline  # 强制只用 vendor/ 离线安装
```

## 五、运行

依赖自检在启动时自动完成，直接执行即可。业务规则全写在 `config/contract_repayment.json`，
改口径 / 改样式只改配置、不动代码。

```bash
# 1) 生成结果（输出文件名取自配置 output_filename；--name 指定文件名里的姓名段）
python scripts/run_skill.py \
    --config config/contract_repayment.json \
    --input  "输入/附件1-合同开票及回款核对表.xlsx" \
    --output-dir 运行成果 \
    --name 姓名

# 2) 交付前自检（46 项全 PASS 才可交付）
python scripts/verify.py \
    --file   "运行成果/合同开票及回款核对表分析结果_姓名.xlsx" \
    --source "输入/附件1-合同开票及回款核对表.xlsx" \
    --config config/contract_repayment.json \
    --json   "运行成果/自检报告.json"
```

`--output-dir` 可省略，省略时结果文件写入当前工作目录（此时先 `cd` 到输出目录，`--config`/`--input` 用相对路径回指）。
运行回执 `运行回执.json` 与结果文件同目录、默认自动生成（`--report` 可改路径）。

> **执行过程只问一件事：姓名。** 结果文件名里的姓名段取自配置 `output_filename`；
> 若该段仍是占位符 `姓名`（或为空），入口会**交互式询问一次**（回车即沿用配置值）；
> 若已是真实姓名则不再打扰。**推荐做法：命令里固定带上 `--name 姓名`**，
> 一次写死、彻底静默，且不受配置占位符影响；也可用 `--no-name-prompt`（沿用配置值）。
> 其余任何信息（口径、样式、路径、表名……）一律不二次确认。

> **产物只留最新一次。** `运行回执.json` 与 `自检报告.json` 每次运行**覆盖式更新**；
> 「输入」与实际输出目录里的旧产物由配置 `output.keep_latest_only`（默认 `true`）自动清理，
> 只保留本次的源表与结果。清理只针对同扩展名的明确产物（输入 `.xlsx`/`.xls`，输出 `.xlsx`/`.json`），
> 不递归、不碰系统目录、本次使用的文件永不删除，且每次删除都会打印。

> **只导出某一张表**（仅按需使用：默认执行只产出完整 8 张表那三份产物）：加 `--only 同合同号合并汇总`，
> 结果另存为 `…_同合同号合并汇总.xlsx`（内含「原始数据」+ 该表，公式与缓存值均保留、可动态重算）。
> 被公式引用的表由引擎**自动带上**，不会出现 `#REF!`；该模式不写运行回执，完整交付物那份不受影响。
Windows 下命令用 `python`。自检退出码 0 = 全部合规；1 = 有不合规项，按报告里的 `id` / `detail` 定位。

## 六、输入

- 单个 `.xlsx`；表头在第 2 行（第 1 行为「单位：万元」说明行），数据从第 3 行开始
- 字段（14 项，与题目清单逐字一致）：序号、区域、客户分类、合同号、开票日期、合同金额、
  未开票金额、开票金额、回款合计、开票未回款、部门、责任人、账龄、未回款原因分类
- 表头行位置、数据末行、各字段所在列**全部动态探测**，不写死行列号
- 源表可能带**无表头的空列**（当前数据集 `max_column = 18`、有效表头 14 个）：
  原样保留在「原始数据」中，不参与美化与核验

## 七、输出

8 张工作表，名称与顺序固定（同题目正文的编号顺序）：
`原始数据`、`同合同号合并汇总`、`未回款原因分类汇总`、
`统计总览`、`区域统计`、`部门统计`、`账龄统计`、`客户分类统计`

- `原始数据`：值、行列顺序、数字格式逐格原样保留（**零美化**，只改表名）
- 其余 7 张：全部统计单元格为动态公式（`SUMIF` / `COUNTIF` / `SUMPRODUCT` / `INDEX+MATCH`），
  并注入缓存值，使程序化读取也能取到数值

## 八、业务规则

| 任务 | 规则 |
|---|---|
| 任务 1 合同号合并 | 主键 `合同号`；5 个金额字段分组求和；文本字段取首条非空；`未回款原因分类` 组内非空去重按「；」拼接；序号 1..N；**按合同号升序** |
| 任务 2 原因分类汇总 | 指标：开票未回款、涉及合同数、涉及数据笔数、占比（分母 = **「原始数据」合同金额合计 − 回款合计合计**）；**按开票未回款降序**；每个分类一条差异化柔和背景条件格式 |
| 任务 3 多维度统计 | 维度 `区域 / 部门 / 账龄 / 客户分类`；7 项指标：合同金额、开票金额、回款合计、开票未回款、合同数、回款率、未回款占比（÷ **全局合同金额**）；**按开票未回款降序** |
| 统计总览 | 8 项：总合同金额、总开票金额、总回款合计、总开票未回款、整体回款率、总合同数、总数据笔数、未回款原因分类数 |

> 「合同数」= 组内**不同合同号**的个数（去重计数），既不是明细行数，也不是合并表行数。
> 空的 `未回款原因分类` 不视为一个分类；分类数一律由数据动态决定，不得写死。

## 九、格式规范

- 金额 `#,##0.000`（千分位 + 3 位小数）；比率 `0.00%`；计数 `0`
- 开票日期保持文本 `yyyymmdd`，数字格式 `@`，**不得**转成日期序列值
- 表头蓝底白字加粗居中；数据区斑马纹交替行（**逐格**一致，R11 断言）；**仅浅灰水平边框**（`FFBFBFBF`）
- 「未回款原因分类」列另叠加**差异化柔和背景条件格式**（每类一色，`EXACT($B3,"分类名")` 命中，R16/R17 断言）
- 文本左对齐 / 数值右对齐 / 日期与分类居中
- 列宽按全角字符自动适配（clamp 8–40）；冻结窗格 `A3`
- 第 1 行为跨列合并大标题（深蓝底白字加粗）

## 十、硬性约束

1. ❌ 禁止硬编码统计数值 → ✅ 全部使用动态公式引用「原始数据」区间
2. ❌ 禁止修改原始明细（值 / 行列顺序 / 数字格式）→ ✅ 逐格原样保留（`verify.py` R2a–R2d 逐格比对）
3. ✅ 8 张工作表名称与顺序严格匹配
4. ✅ 输出路径禁止与输入文件相同
5. ✅ 交付前必须执行 `verify.py`，46 项全 PASS（退出码 0）才可交付

## 十一、常见问题

| 现象 | 原因与处理 |
|---|---|
| `ModuleNotFoundError: openpyxl` / `pandas` | 启动自检应已自动补齐；若仍报错，手动跑 `python scripts/deps_check.py --list` 看缺什么。离线机器需先放好 `vendor/`（见 `vendor/README.md`） |
| 自检报「依赖自检未通过」并退出码 1 | 自动补齐后仍缺依赖。按提示排查：Python 是否为 3.11、`vendor/` 是否完整（离线场景）；也可手动 `install_offline.bat` |
| 自检报找不到 `contract_repayment.json` | `verify.py` 默认读 `config/contract_repayment.json`（与生成侧同一份）；用 `--config` 指定其它路径 |
| 程序读取结果文件时统计值全是 `None` | 缓存值未注入；请使用本 Skill 的产物，`stat_engine.py` 会在保存后自动注入 |
| 「开票日期」显示 `#VALUE!` | 该列被当成日期序列值了；必须保持文本 `yyyymmdd` + `@` |
| 自检 R14 报「未设置列宽」 | 源文件自带的无表头空列已在核验中排除；若输入文件的空列结构不同，同步调整 `verify.py` 的有效列判定 |
| 自检 R17 / R18 报错 | 公式写法回归：R17 = 条件格式公式未锚定区间首行（见 `references/样式规范.md` §7）；R18 = `COUNTIF(S)` 的条件参数是裸区间，空白会被当作 `0` 致 `#DIV/0!`（见 `references/口径与公式规范.md` §2） |
| 「涉及合同数」/「合同数」显示 `#DIV/0!` | 去重计数公式的分母为 0：条件侧必须写成 `维度&""`，否则空白单元格被当作 `0`。修复见 `formula_builder.build_sumproud_distinct_contract_formula` |
| 报「输出文件被占用，无法写入」 | 结果 xlsx 正被 Excel / WPS 打开；关掉该文件后重跑 |
