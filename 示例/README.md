# 示例 / 可配置性验证

本目录用于证明 Skill **不与特定案例、特定规则强绑定**（对应《竞赛须知》「Skill 规则可配置要求」）：
换一套业务配置 = 换一套字段、表名与口径，**主程序代码零改动**。

```
示例/
├── README.md                        # 本文件
├── 案例B-订单流水统计/
    ├── order_settlement.json        # 案例B 业务配置（订单流水：换字段/换表名/换口径）
    ├── 订单流水明细_示例.xlsx        # 案例B 输入（同结构：单表、表头第 2 行、数据第 3 行起）
    └── 运行成果/                    # 案例B 实测产出（结果 xlsx + 运行回执 + 校验报告）
```

> 除换业务字段 / 表名 / 口径外，同一份代码还支持三类改动且**只改配置 JSON**：
> **换行业数据**（表头行可配；表尾汇总行与页脚行可用 `input.data_end` 排除）、
> **新增工作表**（`extra_sheets`：`group` 逐组统计 + `pivot` 行列交叉表）、
> **既有表加 / 删 / 改字段**（合并表、分类汇总、维度表、统计总览）。
> 配置键语义见 `references/配置驱动规范.md`。

## 两套案例的差异（全部落在配置里，代码不动）

| 项 | 案例A（竞赛题） | 案例B（订单流水） |
|---|---|---|
| 配置 | `config/contract_repayment.json` | `示例/案例B-订单流水统计/order_settlement.json` |
| 业务主键 | 合同号 | 订单号 |
| 分组统计字段 | 未回款原因分类 | 异常原因分类 |
| 金额字段 | 合同金额 / 开票金额 / 回款合计 / 开票未回款 | 订单金额 / 发货金额 / 已结算金额 / 未结算金额 |
| 时间字段 | 开票日期 | 下单日期 |
| 维度 | 区域 / 部门 / 账龄 / 客户分类（4 个） | 区域 / 部门 / 库龄 / 渠道分类（4 个） |
| 输出表名 | 同合同号合并汇总、未回款原因分类汇总、区域/部门/账龄/客户分类统计 | 同订单号合并汇总、异常原因分类汇总、区域/部门/库龄/渠道分类统计 |
| 输出文件名 | 合同开票及回款核对表分析结果_赵思敏.xlsx | 订单流水统计分析结果_示例.xlsx |
| 自检 | 46/46 | 46/46 |

> 自检项数 = `30 + 4 × 维度表数`；声明了 `extra_sheets` 时再叠加 `2 + 新增表数`。
> 两套案例均为 4 个维度表 → 46 项。

## 运行方式（与案例A 完全相同的一条命令）

```bash
python scripts/run_skill.py \
    --config 示例/案例B-订单流水统计/order_settlement.json \
    --input  "示例/案例B-订单流水统计/订单流水明细_示例.xlsx" \
    --output-dir 示例/案例B-订单流水统计/运行成果
```

实测结果：输出 8 张工作表，表名与顺序完全按新配置生成
（`原始数据 / 同订单号合并汇总 / 异常原因分类汇总 / 统计总览 / 区域统计 / 部门统计 / 库龄统计 / 渠道分类统计`），
统计单元格仍全部为引用「原始数据」区间的动态公式，公式错误数 0。

> 两套配置的 `output_filename` 署名段都是**固定值**（案例A = 「赵思敏」，案例B = 「示例」），
> 因此**都不会触发姓名询问**，全程静默、可无人值守。
> 需要改名时改配置 `output_filename` 的署名段，
> 或命令里加 `--name XXX` 临时覆盖。详见 `SKILL.md`「六、执行」。

## 交付自检同样可换案例（同一份 verify.py）

```bash
python scripts/verify.py \
    --file   "示例/案例B-订单流水统计/运行成果/订单流水统计分析结果_示例.xlsx" \
    --source "示例/案例B-订单流水统计/订单流水明细_示例.xlsx" \
    --config "示例/案例B-订单流水统计/order_settlement.json" \
    --json   "示例/案例B-订单流水统计/运行成果/自检报告.json"
```

结果：**46 项断言全部 PASS（退出码 0）**。

## 换行业 / 加表 / 改字段（同样只改配置）

三类改动**全部落在 JSON 里**，主程序与自检程序零改动：

1. **换行业**：`input.header_row` 声明真实表头行；源表表尾若带汇总行或页脚行，用
   `input.data_end`（`stop_keywords` / `stop_on_blank_first_col` / `last_row`）声明数据区边界
   —— 不声明边界，汇总行会被当成明细参与统计，结果直接算错；
2. **加表**：`extra_sheets` 声明新表（`group` 逐组一行 / `pivot` 行列交叉表），
   并把表名加进 `profiles.<profile>.sheet_order`；
3. **改字段**：合并表改 `agg_strategy_list`；分类汇总改 `metrics`（可选 `ratio_field_name` /
   `ratio_denominator`）；维度表改 `dim_metrics` + `derived_ratio_list`；总览改 `overview_metrics`；
   并同步把新列头登记进 `*_fields` 与 `field_kind`。

配置键的确切语义、支持的聚合清单与边界，见 `references/配置驱动规范.md`。

`verify.py` 中凡涉及业务字段的断言（业务主键、分类字段、金额字段、指标字段、
排序字段、总览指标口径）一律从配置反查——例如「合并表行数 = 不同**订单号**数」
「**异常原因分类** 汇总 4 项指标」「按**未结算金额**降序」这些断言描述与判据都由配置生成，
代码中不出现任何业务字面量。**断言项数也随配置派生**：
`30 + 4 × 维度表数`，声明了 `extra_sheets` 时再叠加 `2 + 新增表数`
（R5x 行数 / R6x-<表名> 逐格数值 / R7x 排序，同样完全配置驱动）。

## 可配置的边界（明确说明，便于移植评估）

- **完全配置驱动**：字段名、聚合策略、排序字段、分组维度、输出表名与顺序、样式参数、数字格式、
  口径（占比分母）、合并表列序、**新增工作表（`extra_sheets`）**、**数据区边界（`input.data_end`）**
  —— 均在 JSON 中。配置键语义见 `references/配置驱动规范.md`。
- **需要遵守的结构约定**（换案例时同样要满足，属「同结构数据表」前提）：
  1. 输入为**单个工作表**；表头行由 `input.header_row` 声明（**不限于第 2 行**）；
     数据行从表头下一行起，到 `input.data_end` 声明的边界为止；
  2. 表**数量**由 `profiles.<profile>.sheet_order` 声明（不写死 8 张）；声明 `extra_sheets` 时
     可插在任意位置，但剔除它们后其余表的相对顺序仍需与构建顺序一致；
  3. 配置声明的**字段名必须与输入表头逐字一致**（含全角/半角）；
  4. 每张表的列头必须登记进对应的 `*_fields`（驱动格式与对齐，漏登记直接报错），
     每列类型必须登记进 `field_kind`（自检 R8/R9 的唯一判据）。
- **不适用**：非结构化 PDF / 图片识别；`distinct_join` 文本列是唯一登记的公式化例外
  （Excel 无非数组的稳定写法）。

> 案例A 的 8 张表名与顺序是《题目描述》硬性规定的，因此 `config/contract_repayment.json`
> 里 `profiles.spec.sheet_order` 就按题目原样声明；校验器以此为准做严格比对。
> 「换行业 / 加表 / 改字段」的配置入口见 `references/配置驱动规范.md`。
